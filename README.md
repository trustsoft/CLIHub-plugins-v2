# CLIHub Plugins v2

The CLIHub plugin feed (registry v2): a static, CI-generated `index.json` over per-plugin
descriptor folders. Consumed by CLIHub as the default plugin feed (ADR-0015 in the CLIHub
repository).

## Layout

```
index.json                 # generated by CI — never edit by hand
plugins/<id>/plugin.json   # the plugin descriptor (the same file CLIHub installs)
plugins/<id>/feed.json     # optional feed metadata overlay
plugins/<id>/logo.png      # optional
tools/generate-index.ps1   # validation + generation
```

## Adding or updating a plugin

1. Create (or edit) a folder `plugins/<id>/` — `id` must match the folder name.
2. `plugin.json` is the descriptor CLIHub installs: required fields `id`, `name`, `description`,
   `version` (major.minor.patch), `publisher`, `homepage`, and `commands.launch.executable`
   (`resume`/`version`/`update` commands are optional but need `executable` when present).
3. Optionally add `feed.json`:

```json
{
  "compatibility": ">=1.1.0",
  "channel": "stable",
  "releaseNotesUrl": "https://...",
  "package": { "url": "https://.../plugin.zip", "sha256": "<64 hex>" }
}
```

- `compatibility` — CLIHub version range, comma-separated constraints (`>=1.1.0 <2.0.0`).
  Defaults to `>=1.0.0`.
- `package` — only for plugins that ship a zip package; descriptor-only plugins omit it (the
  descriptor embedded in `index.json` is what CLIHub installs).
4. Open a PR. CI validates the descriptors; after merge, CI regenerates `index.json` and pushes
   it automatically.

`logo.png` (optional) becomes the entry's `logoUrl`.

## Index signing

`index.sig` is an ECDSA P-256 signature envelope over the exact `index.json` bytes:

```json
{ "algorithm": "ecdsa-p256-sha256", "signature": "<base64 DER>", "signedAt": "..." }
```

- CI signs after index generation when the `INDEX_SIGNING_KEY` secret is present (base64-encoded PEM
  private key); without the secret the step is skipped (transition window) and the workflow still
  publishes an unsigned index.
- `public.pem` (committed at the repo root) is the verification anchor; CLIHub embeds the same key.
- `-Verify` mode (used by the PR check) validates `index.sig` against `public.pem`.
- `index.json`/`index.sig` are pinned to LF in `.gitattributes`: any line-ending change invalidates
  the signature byte-for-byte.

Key generation (one-time, maintainer):

```bash
openssl ecparam -name prime256v1 -genkey -noout -out private.pem
openssl ec -in private.pem -pubout -out public.pem
base64 -w0 private.pem   # paste into the INDEX_SIGNING_KEY repository secret
```

Never commit `private.pem`.

## Local regeneration

```powershell
./tools/generate-index.ps1
./tools/sign-index.ps1            # signs only when INDEX_SIGNING_KEY is set
```

Both scripts are idempotent: they rewrite their outputs only when the content actually changes.
